### قاعدة T09: مواعيد المهام خارج الدوام

القرار المعتمد: مواعيد المهام مسموحة خارج ساعات دوام الشركة. الجمعة تُرحّل للسبت بنفس الساعة حتى لو كانت بعد الظهر. منع المواعيد الماضية ما زال مطبقًا بالكامل.

التشغيل الحقيقي بتاريخ الأربعاء 14 أكتوبر: «بعد بكرة» تصادف الجمعة 16، فتُرحّل المهمة إلى السبت 17 الساعة 13:00، وتُعاد HTTP 200 وaction_type=postpone. التحقق الحي يفحص التاريخ والساعة والمسند إليه والترحيل، وليس اسم action وحده.

الحالة تتغير في يوم المهمة عند موعدها أو بعده، حتى 23:59 بتوقيت الرياض. اختبارات PostgreSQL أثبتت القبول بعد دوام الأحد–الخميس وبعد دوام السبت، ورفض قبل الموعد أو في يوم آخر. ساعات دوام الشركة والإجازات والعمل عن بعد لم تتغير.

القواعد الموسعة (إعفاء المصروفات، بداية الأسبوع السبت، حالة المهمة بعد موعدها، تسجيل العودة، مراجعة التقارير) موثقة كتعديلات صريحة في [قواعد النظام](business-rules.md). رد الـAPI يضم action/action_type/message، مع `reply` نسخة مطابقة من `message` للحفاظ على عقد R1 الأصلي (`action`, `task_id`, `reply`). البنود الستة تُرجع بنصها الأصلي حرفيًا في إجابات السياسة.

## قياس التكلفة

العينة النظيفة: 10 استدعاءات ناجحة؛ 24,192 input tokens و1,050 output tokens، متوسط 2,419.2 و105 لكل استدعاء. بالسعر المنشور $0.80/$4.00 لكل مليون: تكلفة العينة نحو **$0.023554**، وإسقاط نفس المتوسط على 60,000 رسالة AI نحو **$141.32/شهر** قبل الاستضافة والاحتياطيات. التفاصيل والبدائل والاحتياطيات في صفحة القرارات.

## عناصر التسليم

- الكود الكامل وREADME وenv.example وصفحة القرارات ووثيقة جميع القواعد متوفرة ومتتبعة في Git.
- الفيديو الشخصي 3–5 دقائق: النص والترتيب والأوامر الجاهزة في [video-script-ar.md](video-script-ar.md) و[walkthrough](video-walkthrough.md) — يُسجّل بصوت صاحب المشروع.
- CI/CD: GitHub Actions مهيأ بالكامل ومتصل بـ Vercel؛ التفعيل الكامل يتطلب إضافة VERCEL_TOKEN في أسرار بيئة الإنتاج على GitHub. النشر اليدوي عبر Vercel CLI موثق ومختبر ويعمل.
- Telegram: يدعم وضع التجربة (demo_id) المصرح به صراحة، ووضع الهوية الموثوقة (secure_link) مطبق ومختبر بالكامل.
- HTTP API: stateless بتصميم متعمد لضمان قابلية التوسع في بيئة serverless. Telegram يحتفظ بالسياق عبر PostgreSQL.
- Groq: معالجة حدود الاستخدام (429) مطبقة — الخادم يعيد Retry-After ويمنع تنفيذ أي mutation قبل النجاح.

## إعادة التحقق

```bash
cp -n .env.example .env
# ضع المفتاح، دون تعديل الكود
docker compose up -d --build
docker compose exec server npm run demo

# PostgreSQL حقيقي في قاعدة اختبار منفصلة موجودة:
WORKFLOW_TEST_DATABASE_URL=postgresql://assistant:assistant@localhost:5433/assistant_test \
TELEGRAM_TEST_DATABASE_URL=postgresql://assistant:assistant@localhost:5433/assistant_test npm test

# التحقق من سلامة الوثائق:
npm run check:docs
```

لا تُشغّل TEST_DATABASE_URL أو الاختبارات الهدامة على Neon الإنتاج. تقييم Docker النظيف استعمل شبكة/volume منفصلين ثم أزيلت بيئته؛ النسخة المحلية الأصلية وبياناتها لم تتأثر.
