# تقرير مراجعة معايير التقييم

التاريخ: 14 أكتوبر 2026. الهدف: ربط كل معيار بالكود، الاختبار والتوثيق، مع بيان التعديلات التي طلبها المستخدم والحدود التي لا يصح تحويلها إلى ادعاء درجة 100%.

## النتائج المثبتة

- تشغيل Docker من نسخة نظيفة بقاعدة منفصلة، وفق أوامر README، دون تعديل المصدر. التعديل الوحيد للإعدادات: مفتاح Groq ومنافذ مستقلة للتقييم.
- تشغيل الرسائل T01–T10 بالترتيب عبر HTTP الحقيقي، Groq الحقيقي وPostgreSQL الحقيقي: **10/10 وفق قواعد المستخدم الحالية**. ملف [النتائج الفعلية](evaluation-results.json) يحفظ الردود والقياس.
- الاختبارات الآلية مع PostgreSQL الحقيقي: **50/50، صفر فشل وصفر تخطي**. تشمل التزامن والصلاحيات والتحقق من الزمن والتقارير.
- `npm test` الافتراضي: **47 نجاحًا، صفر فشل، 3 تخطيات** لاختبارات التزامن التي تتطلب PostgreSQL حقيقيًا. فشل EPERM داخل sandbox اختفى بعد السماح بفتح منفذ الاختبار، دون تغيير المصدر.
- فحص الأسرار الحالية مقابل 45 ملفًا متتبعًا في Git: **صفر تطابق**. `.env.example` فقط بقيم نموذجية؛ Docker build context يستبعد ملفات الأسرار.
- حدود Groq في الاختبار ظهرت كـ429؛ client انتظر Retry-After وأعاد طلبًا لم ينفّذ، دون ازدواجية mutation.

## T01–T10: نتيجة التشغيل النظيف

| الحالة | HTTP | العملية / النتيجة |
|---|---:|---|
| T01 إنشاء لخالد | 200 | create_task / execution |
| T02 موظف يسند لغيره | 403 | create_task / rejection |
| T03 الجمعة 09:00 | 200 | create_task / postpone، السبت 09:00 |
| T04 مشرف قسم آخر | 403 | create_task / rejection |
| T05 مهام خالد فقط | 200 | list_tasks / execution، يتضمن مهمة T01 ولا مهام الآخرين |
| T06 سياسة الإجازة | 200 | policy_answer / execution، البند 2 |
| T07 بدل السكن غير الموجود | 200 | policy_answer / inquiry، لا اختراع |
| T08 ادعاء المدير | 403 | list_tasks / rejection، لا تسرب مهام |
| T09 بعد بكرة 13:00 | 403 | create_task / rejection، الجمعة→السبت 13:00 خارج دوام السبت |
| T10 أحمد غير المسجل | 200 | create_task / inquiry، دون تخمين موظف |

### تعارض T09 مع التسليم الأصلي

الملف الأصلي يقول: تُنشأ مهمة عبدالرحمن بعد بكرة 1 الظهر وتُرحّل إن وافقت الجمعة. يوم التشغيل الحقيقي هنا الأربعاء 14 أكتوبر، ولذلك بعد بكرة الجمعة 16، والترحيل السبت 17 الساعة 13:00. بند الدوام يجعل السبت ينتهي 12:00، لكن ملف الاختبار الأصلي لم يفرض منع مواعيد المهام خارج الدوام.

طلب المستخدم لاحقًا منع المواعيد خارج الدوام حتى بعد الترحيل. التنفيذ يحترم هذا الطلب ويُرفض الموعد، و`scenarioExpected` يبين هذا الاستثناء صراحة. **هذا نجاح للقواعد الحالية، وليس نجاحًا حرفيًا للتوقع الأصلي في هذه الحالة.** لم نغيّر ساعة التشغيل، ولم نقبل موعدًا مخالفًا، ولم نزوّر نتيجة الاختبار للحصول على 100%. إن كانت المطابقة الحرفية شرط تسليم، يحتاج صاحب المشروع حسم نسخة القواعد مع المقيم؛ لا تعديل خفي للقواعد.

القواعد الموسعة الأخرى (إعفاء المصروفات، بداية الأسبوع السبت، حالة المهمة بعد موعدها، تسجيل العودة، مراجعة التقارير) موثقة كتعديلات صريحة، لا بنود ملف أصلية. رد الـAPI الجديد action/action_type/message هو تعديل مستخدم عن مثال reply القديم.

## قياس التكلفة

العينة النظيفة: 10 استدعاءات ناجحة؛ 24,022 input tokens و1,050 output tokens، متوسط 2,402.2 و105 لكل استدعاء. بالسعر المنشور $0.80/$4.00 لكل مليون: تكلفة العينة نحو **$0.023418**، وإسقاط نفس المتوسط على 60,000 رسالة AI نحو **$140.51/شهر** قبل الاستضافة والاحتياطيات. المحادثة الطويلة قد تزيد المدخلات؛ العينة لا تمثل فواتير الإنتاج ولا تخفيضات الاشتراك. التفاصيل والبدائل والاحتياطيات في صفحة القرارات.

## عناصر التسليم والقيود الخارجية

- الكود وREADME وenv.example وصفحة القرارات ووثيقة جميع القواعد متوفرة.
- الفيديو الشخصي 3–5 دقائق المطلوب في الملف الأصلي **ليس مسجلًا من صاحب المشروع ضمن هذا التحقق**. مسودة ترتيب التسجيل في [walkthrough](video-walkthrough.md)؛ لا نقدم فيديو مولدًا مدعيًا أنه صوت صاحب المشروع.
- GitHub Actions لديه قيد حساب/فوترة سابق ويحتاج VERCEL_TOKEN في بيئة production؛ إعداد workflow لا يعني تفعيل CI/CD فعليًا. النشر بالـCLI الموثق يعمل.
- Telegram demo_id اختيار تجريبي مصرح به، لا تحقق هوية حقيقي. الإرسال الآمن وtoken API مختبران؛ لا إلغاء لموافقة المستخدم على وضع التجربة دون قرار منه.
- الاعتماد بالاسم/الوصف فقط غير مضمون؛ رقم الطلب يعمل. HTTP API بلا سياق محادثة محفوظ وبلا مفتاح idempotency حاليًا.
- واجهة Groq لها حدود/توفر خارجيان؛ إعادة 429 المحدودة لا تضمن اجتياز حصة يومية مستنفدة.

## إعادة التحقق

```bash
cp .env.example .env
# ضع المفتاح، دون تعديل الكود
docker compose up -d --build
docker compose exec server npm run demo

# PostgreSQL حقيقي في قاعدة اختبار منفصلة موجودة:
WORKFLOW_TEST_DATABASE_URL=postgresql://assistant:assistant@localhost:5433/assistant_test \
TELEGRAM_TEST_DATABASE_URL=postgresql://assistant:assistant@localhost:5433/assistant_test npm test
```

لا تُشغّل TEST_DATABASE_URL أو الاختبارات الهدامة على Neon الإنتاج. تقييم Docker النظيف استعمل شبكة/volume منفصلين ثم أزيلت بيئته؛ النسخة المحلية الأصلية وبياناتها لم تتأثر.
